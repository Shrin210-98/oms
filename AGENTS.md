# Working on OMS

OMS is a learning-first portfolio project for one B2B supplier. Work in small, independently testable milestones. Obtain the owner's approval before beginning each major milestone.

- Explain the business problem and the reason for each proposed dependency or abstraction before adding it.
- Give the owner a hands-on exercise for central business rules. Offer hints before a full solution during learning exercises.
- Review the owner's code and explain mistakes. Show how to trace failures with a debugger, a request ID or a SQL query.
- Teach the relevant JavaScript, strict TypeScript, React, Node.js, SQL and deployment concepts alongside the feature. Include an acceptance demonstration and an interview question for each milestone.
- Keep edits focused, readable and idiomatic. Use Express services and Prisma transactions where a business operation requires them. Teach the equivalent SQL.
- Use synthetic business data. Keep secrets, personal data and deployment environment files out of version control.
- Keep the OMS independently operable. Add inventory, warehouse operations or TMS integration only after an explicit scope decision.
- Run the checks in the README and summarize the results and remaining limitations at each milestone review.
